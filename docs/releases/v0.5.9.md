# Pi-Vis v0.5.9

## Highlights

- Updated the pinned Pi runtime to 1.4.0. Pi-Vis now inherits Pi’s latest model, codemode, MCP, tool-selection, terminal, and provider improvements while continuing to use the embedded app shell.
- Added **Force restart host** to live and pending session rows. It can recover a stuck, failed, or starting session by stopping the host and its child processes, while retaining saved conversation history and unsent editor content.
- Model and thinking selections now become the defaults for newly created sessions. Existing sessions retain their own selections.
- Added extension-provided tool-card views. Registered Pi tool renderers can add a bounded **Extension view** to tool results, including restored results; tool cards now also show recorded execution duration.
- Added Pi 1.4 session sharing destinations: `/share` can use Gist, Radius, or automatic selection based on the public Pi setting. Radius sharing uses the authenticated provider and does not fall back or replay an ambiguous upload.

## Reliability and compatibility

- Improved session replacement, reload, attachment, history hydration, notifications, and command admission so delayed events from an old host cannot overwrite a successor session.
- Hardened direct Shell Turns (`!` and `!!`) around busy-state admission, cancellation, durable start/finish records, and recovery after interrupted execution.
- Migrates the renamed Azure provider ID (`azure-openai-responses` to `azure`) safely for saved defaults, model references, and valid global credentials. Existing `azure` credentials remain authoritative.
- Preserved the JSONL-tail repair, fragmented Mistral tool-call, and custom-message/tool-result adjacency regressions against the pristine Pi runtime. The packaged runtime also verifies patched dependency resolution and Zod 4 validation behavior.

## Upgrade notes

- No migration is required for sessions, project-trust decisions, or general settings.
- Custom Azure entries in `models.json` should use provider key `azure`; custom Kimi Code base URLs must include `/v1`.
- Custom Pi themes must follow Pi 1.4’s current published theme schema.
- Session sharing remains opt-in. Choose `gist`, `radius`, or `auto` through Pi’s `sessionShareDestination` setting.
